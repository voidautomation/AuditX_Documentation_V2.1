Prerequisites

Prerequisites & Environment Setup

Critical — Complete All Prerequisites Before First Use

Failure to complete the following steps will result in execution failures, missing screenshots, or incomplete audit evidence.

1. System Requirements

Windows 10/11 with Interactive Session

Required for Foreground execution mode (SAP GUI must be visible on screen) and Word Interop (COM automation requires an interactive desktop session). Remote Desktop (RDP) sessions are supported but must have an active display.

Required
.NET Framework 4.8

The application targets .NET Framework 4.8. Verify via: Control Panel → Programs → Turn Windows features on/off → .NET Framework 4.8
Or run: reg query "HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full" /v Release

Required
Visual C++ Redistributable 2013 or Later

Required by SAP NCo (sapnco.dll). Install both x86 and x64 versions from Microsoft. If missing, you will see "The specified module could not be found" errors when starting Housekeeping tab.

Required
Microsoft Word — Installed and Licensed

Microsoft Office 2016 or later. Word must be fully licensed and activated — trial/expired versions will throw COM Interop exceptions. Used for all audit evidence documents and monthly reports.

Required
SAP GUI Installed — saplogon.exe Accessible

SAP GUI for Windows 7.70 or later. Default path:
C:\Program Files (x86)\SAP\FrontEnd\SAPgui\saplogon.exe
Configurable in Settings tab under SAP Logon Path.

Required
SAP Scripting Enabled — Client Side

Go to: SAP Logon → Options → Accessibility & Scripting → Scripting

  • ✅ Enable scripting — must be checked
  • ⬜ Notify when a script attaches to SAP GUI — uncheck for silent automation
  • ⬜ Notify when a script opens a connection — uncheck
Required
SAP Scripting Enabled — Server Side

The SAP parameter sapgui/user_scripting must be TRUE. Verify via transaction RZ11. Contact your SAP Basis team if this is disabled — it requires a system restart on some versions.

Required
Application Configuration (My.Settings) Populated

Navigate to Settings Tab and configure all required fields before first execution:

  • Start Time / End Time (HH:mm:ss)
  • SAP GUI XML path (saplogon.xml)
  • ITGC Control XML path
  • SAP Logon executable path
  • Download destination folder
  • SAP OSS ID (for ITGC01)
  • T-Code list (for ITGC04)
  • Approved Users per control (ITGC08–17)
Required
Write Access to Report Output Directory

Default path: %USERPROFILE%\Downloads\ITGC REPORT
Subfolders are created automatically: ITGC REPORT → {Month, Year} → {ControlID}
The user running AuditX must have full write access to this folder tree.

Required
Write Access to Log Directory

Log files are written to: C:\Void\Logs\
The directory is created automatically on first run, but the executing user needs write access to C:\Void\. If blocked by policy, configure an alternate path.

Required

2. SAP GUI Security Settings — Allow Automation Directory

🔒 Update SAP GUI Security Settings

SAP GUI has a security layer that may block external scripts from controlling the GUI session. You must add an explicit "Always Allow" rule for the AuditX application directory to prevent permission dialogs during automation.

1
Open SAP Logon Options

Open SAP Logon, then navigate to:
SAP Logon → Options (F12) → Security → Security Settings

2
Add New Security Rule

Click "Add Rule" or "+" button and set the following:

Rule ActionAlways Allow
Object TypeScript / Application
Path / DirectoryC:\AuditX\  (or your actual installation path)
ScopeAll files in directory and subdirectories
3
Verify the Security Rule Configuration

Your security settings dialog should look like the screenshot below. The AuditX directory must appear in the Allowed list with Always Allow permission.

SAP GUI → Options → Security → Security Settings Figure P-1
Screenshot not found
Place your screenshot at: img/placeholder-sap-security.png
Figure P-1: SAP GUI Security Settings — "Always Allow" rule added for the AuditX automation directory. This prevents security prompts during scripting.
4
Click OK and Restart SAP Logon

Click OK to save the security settings. Restart SAP Logon for the changes to take effect. Run AuditX and verify no security prompt appears when execution begins.

SOP-01

Application Login

Purpose: Authenticate and access the AuditX dashboard
Role: All Users
Frequency: Each Session
1
Launch AuditX Application

Double-click AuditX.exe from the installation directory. The Login Form will appear on screen.

AuditX Login Form Figure 1-1
Screenshot not found
Expected: img/placeholder-login.png
Figure 1-1: AuditX Login Form with Windows Authentication button
2
Click Login — Enter Windows Credentials

Click the Login button. A Windows credential dialog appears with your DOMAIN\Username pre-filled. Enter your Windows password.

Uses native Windows CredUI API. Your credentials are validated against Active Directory via LogonUser Win32 API — not stored anywhere by AuditX.

3
Automatic License Validation

After Windows authentication succeeds, the system automatically:

  1. Reads license.cert from the application directory
  2. Decrypts using AES-256 with Rfc2898DeriveBytes
  3. Verifies SHA256 signature matches expected hash
  4. Confirms Windows ID matches DOMAIN\Username
  5. Makes REST GET to Firebase RTDB to verify expiry date
Dashboard Opens — Login Successful

The Home Dashboard opens with all 7 tabs accessible. Click your profile avatar (top-right) to view your name, email, and license expiry date.

SOP-02

Configure SAP System (Home Tab)

Purpose: Select SAP system and configure execution parameters
Tab: Home
1
Select Execution Type

In the Execution Setting group, choose from the first dropdown:

  • Individual Control — Run one specific ITGC control
  • All Controls — Run all 15 active controls in sequence
2
Select Execution Mode
  • Foreground — SAP window fully visible; uses PrintScreen via keyboard simulation
  • Background — SAP window can be behind others; uses Win32 PrintWindow API with timestamp overlay
3
Select ITGC Control

Choose from the Select ITGC Control dropdown (e.g., ITGC01 - SAPOSS Enabling Audit). The control description auto-populates below the dropdown.

4
Select SAP System

Choose the target SAP production system from the Select SAP System dropdown. The System ID displays to the right. Optionally check Client to manually override the default client number.

5
Enter SAP Credentials

Enter your SAP User ID (default: ITGCBOT) and Password.

These are SAP credentials, NOT Windows credentials. The account needs sufficient authorization for all transactions used by the selected ITGC control.

6
Set Report Duration

In Report Duration, set the From and To dates. The Report Month label auto-calculates (e.g., "July, 2025") and the output folder path updates automatically.

SOP-03

Execute Individual ITGC Control

Purpose: Run a single ITGC audit control with evidence capture
Estimated Time: 2–5 minutes per control
1
Complete SOP-02

Ensure all fields in the Home tab are properly configured per SOP-02.

2
Click the "Execute" Button

The system validates all inputs, then automatically:

  1. Launches SAP Logon application (waits 3 seconds)
  2. Attaches to SAP GUI via COM (up to 3 retry attempts)
  3. Logs in with provided SAP credentials
  4. Navigates to the required SAP transaction
  5. Captures screenshots at each defined step
  6. Saves evidence as a Word document
  7. Records Green/Red status in monthly CSV
SAP GUI Automation in Progress Figure 3-1
Screenshot not found
Expected: img/placeholder-execute.png
Figure 3-1: SAP GUI scripting executing an ITGC control — Word document open with step descriptions and screenshots
Review Output

The Word report saves to the folder path shown in the Report Duration section. Click the folder icon to open the output directory directly.

SOP-04

Execute All Controls (Batch Mode)

Purpose: Run all 15 active ITGC controls in one session
Estimated Time: 30–60 minutes
1
Set Execution Type to "All Controls"

The ITGC Control dropdown becomes disabled and auto-populated with all active controls. The system iterates each in sequence.

2
Configure SAP Credentials and Date Range

Same as SOP-02. Ensure the SAP account has authorization for all transactions used across all controls.

3
Click Execute

The system iterates through each control. Failed controls are logged with full stack trace but execution continues with the next control.

Completion

A dialog confirms all controls executed. Individual Word reports are saved in control-specific subfolders under the reporting month directory.

Purpose: Create consolidated monthly ITGC audit Word report

Set Date Range

2

The system reads ITGC_Audit_Comments_{Month}.csv and generates a Word report with these sections:

  1. Cover image (cover.png)
  2. Document control table (Client, Prepared/Reviewed/Approved By)
  3. Summary dashboard (Total, Green count, Red count)
  4. Detailed records table (6 columns, color-coded by status)
  5. Action summary grouped by Control ID and System

Purpose: Configure SAP RFC connections for Housekeeping analysis
Tab: Housekeeping → RFC Settings button

Navigate to Housekeeping Tab

Add New SAP System

Click Add and fill in all required fields:

App Server HostSAP application server hostname or IP
System Number2-digit system number (e.g., "00")
Client3-digit client (e.g., "100")

User Inactivity Analysis

Tab: Housekeeping

Select SAP System

2
Configure Filters

User TypesSelect: Dialog (A), Service (S), Background/Comm (C), System (B)
Exclude LockedCheck to exclude already-locked users from results
ValidityValid users (no expiry / future expiry), Invalid users (expired), or both

SOP-09

Lock / Manage Users

Purpose: Lock users, change validity, or reassign user groups in SAP
Requires: SOP-07 analysis completed
1
Select Users in the Result Grid

After running SOP-07, select one or more rows in the result grid. Multi-select by holding Ctrl or clicking multiple rows.

2
Choose Action from the Action Panel
🔒 Lock User

Calls BAPI_USER_LOCK + commit

Change Validity

Sets GLTGB to target date

Change User Group

Moves users to INACTIVE group

Confirm and Review Results

Confirm the action dialog. A summary shows success/failure for each user. The analysis automatically re-runs to reflect the changes.

⚠️ Irreversible Actions

User lock and group changes are applied directly to SAP via BAPI calls. Always confirm the user list carefully before proceeding. Lock User is not available in Multi-System Analysis mode.
